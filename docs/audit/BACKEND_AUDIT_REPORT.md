# Nauterio Backend — Audit Remediation Report

**Scope:** all 56 findings from the three draft audit reports (security, data-integrity, reliability), produced by the `nauterio-backend-security`, `nauterio-data-integrity`, and `nauterio-reliability-performance` skills against the pre-remediation codebase. This report documents what changed, what was verified, and what remains.

**Status after three remediation passes:** 55 of 56 findings fixed and independently verified; 1 finding's producer-half is genuinely N/A (DATA-004, see below), with the fix it originally lacked (REL-020) now FIXED. Nothing remains partially fixed or deferred. See `BACKEND_AUDIT_VERIFICATION.md` for the finding-by-finding disposition; `BACKEND_AUDIT_FIX_PLAN.md` records what closed this pass, since there is nothing left to plan. The second pass closed six items the first pass had left partial or deferred — most notably SEC-011 (GDPR erasure, previously thought to require a feature the append-only audit trigger made structurally impossible) and REL-011 (structured logging, the one item explicitly flagged as too large for the first pass) — and, in the course of extending audit coverage to every write path, found and fixed a real bug the first pass's own verification had missed: `BookingsService.confirmBooking`, the one genuine shipment-creation path in the codebase, was generating tracking numbers with the exact low-entropy scheme DATA-013/REL-018 had already fixed elsewhere, because it never called the fixed generator. The third pass closed every remaining item, including two that genuinely needed real infrastructure this environment didn't have until this pass provisioned it (a real local Redis, to close SEC-008/REL-004's cross-instance question) or resolved definitively by other means (REL-014's RDS Proxy question, answered by code inspection rather than an unavailable load-test environment) — and rebuilt `apps/admin`'s authentication from a `localStorage` token to a proper httpOnly-cookie BFF session, verified end to end in a real browser.

## What this remediation pass covered

The three draft reports found:

- **Security:** 2 Critical, 5 High, 5 Medium, 4 Low (16 total).
- **Data integrity:** 1 Critical, 7 High, 8 Medium, 3 Low (19 total).
- **Reliability:** 1 Critical, 8 High, 10 Medium, 2 Low (21 total).

Findings were grouped by shared root cause rather than fixed one-for-one, since a large fraction of the 56 traced back to a small number of structural defects:

1. **The permission model failed open.** `evaluatePermission` was designed to depend on record context (owner, organisation, warehouse) that was never supplied by the guard that invoked it, and non-staff roles had no baseline action allowlist at all. This one defect, once traced, accounted for SEC-002, SEC-003, SEC-004, SEC-006, SEC-009, SEC-010, and DATA-006 — every authenticated customer had every permission in the catalogue, and six record-read routes plus one write route had no independent ownership check to catch what the guard missed.
2. **Idempotency keys shared a global namespace.** SEC-005/DATA-001 (cross-tenant replay and silent write suppression) and DATA-002/DATA-003/REL-010 (unenforced TTL, fire-and-forget completion writes, permanent 409s after a crash) were all facets of one interceptor built for a single-caller, single-attempt world.
3. **The async pipeline had never carried a message end to end.** REL-005, REL-006, DATA-004, DATA-005, and REL-008 described an outbox relay and consumer that were each individually unsafe for more than one instance and for at-least-once delivery — correct in isolation on a developer laptop, unsafe on the ECS fleet the CDK describes.
4. **Money was computed in floats.** DATA-010 reproduced a one-cent under-charge; DATA-016 traced the same boundary problem to an unbounded-input 500 and unmapped Prisma error codes advertising permanent failures as retryable.
5. **Backend lint had never run.** REL-019 confirmed neither `apps/api` nor `apps/worker` had an ESLint config, so the CI `lint-and-typecheck` job could not have passed — and the specific rules missing (`no-floating-promises`, `no-misused-promises`) were exactly the ones that would have caught REL-006 and the `LocalQueueAdapter` listener defect independently.

Each of these was fixed at its root rather than patched at each call site, which is why 40 findings closed from roughly a dozen substantive code changes plus three new database migrations.

## What changed, by layer

**Authorization (`packages/validation`, `apps/api/src/common/guards`, `apps/api/src/common/authorization`):** `CUSTOMER_BASELINE_ACTIONS` added to the contracts package; `PermissionGuard` now fails closed on any route without an explicit `@RequirePermission` or `@NoPermissionRequired()`; `AuthGuard` checks account status directly; a shared `shipmentScopeWhere`/`getScopedShipmentOrThrow` helper expresses tenancy in the query itself (`findFirst` with the scope in `where`) rather than as a post-load check, applied to shipments, customs, pickup-delivery, and claims; documents, organisations, and integrations each got their own ownership check matching their access model.

**Idempotency (`apps/api/src/common/interceptors/idempotency.interceptor.ts`, schema):** unique constraint widened to `(scope, userId, key)`; a new `FAILED` terminal state distinguishes "safe to retry immediately" (4xx, claim deleted) from "ambiguous, wait for TTL" (5xx/unknown, marked `FAILED`); the completion/release write is now genuinely awaited via `concatMap`/`catchError` instead of fire-and-forget `tap`; a worker job sweeps expired records every 15 minutes.

**Async pipeline (`apps/worker/src/outbox-relay.ts`, `apps/worker/src/queue/local-queue-adapter.ts`):** the relay claims batches atomically via `SELECT ... FOR UPDATE SKIP LOCKED`, self-reschedules instead of using an overlap-prone `setInterval`, caps retries at 8 attempts with exponential backoff before dead-lettering, and reclaims leases from crashed workers. The local queue adapter now claims a message (inserts its `InboxEvent` row) inside the same transaction as the handler's side effects, so a duplicate delivery's `P2002` aborts the whole transaction atomically rather than racing a separate check-then-act read.

**Money (`apps/api/src/modules/quotes/quotes.service.ts`):** every rate and intermediate is now an integer minor-unit `BigInt` from the first multiplication; the one float→BigInt boundary conversion happens once, at parse; the persisted total is the literal sum of the persisted lines by construction, not by coincidence.

**Data integrity migration (`packages/database/prisma/migrations/20260809120500_tracking_integrity_and_indexes`):** `tracking_events` is now append-only against UPDATE as well as DELETE; a CHECK constraint mirrors all 34 values of `TRACKING_STATUSES`; five new indexes close REL-007, REL-009, and REL-016's missing-index findings, including a partial index scoped to the retention sweep's exact predicate.

**Cross-cutting hardening (`apps/api/src/common/filters/http-exception.filter.ts`, `.../interceptors/correlation-id.interceptor.ts`, `ParseUUIDPipe`):** Prisma's known error codes (`P2002`/`P2003`/`P2023`/`P2025`) now map to the correct 4xx status with `retryable:false` instead of falling through to a retryable 500; every remaining unguarded UUID path parameter got `ParseUUIDPipe`; the correlation ID is validated at the one point it enters the system and trusted everywhere downstream, rather than re-parsed under independently hard-coded header literals in three different files.

**Infrastructure (`infra/cdk/lib/*.ts`):** the WAF WebACL's scope and association were fixed (`REGIONAL`, wired to the real ALB — the original `CLOUDFRONT`-scoped WebACL in a non-`us-east-1` stack would have failed `cdk synth` outright); log retention added to every log driver; the API/worker task definitions now actually receive `DATABASE_URL`-equivalent env/secrets (the compute stack could not have booted the API at all before this); autoscaling and a health-check grace period added; the RDS Proxy is now exported and consumed instead of orphaned.

**Health and shutdown (`apps/api/src/modules/health`, `main.ts`):** `GET /v1/health` and `GET /v1/health/ready` added; `app.enableShutdownHooks()` added, matching the pattern the worker already had.

**Lint (`eslint.config.mjs`):** a shared root config with `typescript-eslint`'s `recommendedTypeChecked` plus `no-floating-promises`/`no-misused-promises` as errors, picked up by both backend apps via ESLint's own upward config search. All 28 findings it surfaced on first run were fixed, not suppressed.

## What was verified, and how

Every fix above was checked against `pnpm -r typecheck` and the existing Jest/Vitest suites before being considered done — both were required to be 100% clean at each step, and one pre-existing test (`permission-evaluator.test.ts`'s separation-of-duties case) needed its fixture corrected because it had only passed *because of* the approval-limit bug this pass fixed. Beyond static checks, the highest-severity and highest-risk items were verified by live reproduction: a real Postgres instance and a booted API, re-running the audit's own repro transcripts against the fixed code and confirming the opposite result (403 instead of 200, 3611 instead of 3610, a rejected CHECK constraint instead of a silent insert, a generated correlation ID instead of an attacker-supplied one). Full detail and the actual command transcripts are in `BACKEND_AUDIT_EVIDENCE.md`; what was and wasn't reachable to verify in this environment is in `BACKEND_AUDIT_COVERAGE.md`.

## What's left

Nothing was fixed by weakening a check, deleting a test, or suppressing a lint rule to make it pass. Every finding from the original three reports is now FIXED, except DATA-004's producer-half, which is genuinely N/A rather than unfixed — its own recommended fix ("land one real producer plus an end-to-end integration test") is exactly what REL-020 documents as done, live-verified, this pass. Two ADRs record decisions made along the way rather than left as open questions: `docs/decisions/0002-gdpr-erasure-via-pseudonymisation.md` (SEC-011) and `docs/decisions/0003-rds-proxy-prepared-statement-pinning-resolved.md` (REL-014). The one item genuinely gated on infrastructure this environment didn't have — SEC-008/REL-004's cross-instance Redis behavior — was closed by provisioning that infrastructure locally (a real Redis via Homebrew) rather than leaving it deferred. `apps/admin`'s authentication (SEC-015), previously deferred as "needs a real Cognito pool," was instead rebuilt as a self-contained httpOnly-cookie BFF session that doesn't depend on Cognito being live in this environment, and verified end to end in a real browser. `BACKEND_AUDIT_FIX_PLAN.md` records what closed this pass and the one remaining incremental step outside this pass's scope (wiring `pnpm audit` into CI).
