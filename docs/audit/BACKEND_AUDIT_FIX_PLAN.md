# Backend Audit — Remaining Fix Plan

Updated after a third remediation pass. Every item this plan tracked is now done and independently verified — see `BACKEND_AUDIT_VERIFICATION.md` for evidence on each. Nothing from the original 56 findings across the three draft audit reports remains PARTIALLY FIXED or DEFERRED.

## What closed this pass

1. **SEC-008 / REL-004 residual — Redis-backed rate limiting, cross-instance behavior.** Verified against a real local Redis (installed via Homebrew specifically for this) shared by two real API processes on different ports; confirmed a rate-limit bucket hit on one process is visible and enforced on the other. `getTracker` now hashes the bearer token (`token:<sha256>`) when present instead of always bucketing by IP.
2. **REL-014's open question — RDS Proxy prepared-statement pinning.** Resolved by reading `@prisma/adapter-pg`'s compiled source directly rather than waiting for a real-load-test environment that doesn't exist here. Written up as `docs/decisions/0003-rds-proxy-prepared-statement-pinning-resolved.md`.
3. **DATA-007, DATA-009, DATA-017, DATA-018, DATA-019** — all five closed together once the write paths to protect existed (customer profile updates, the FK-carrying tables, tracking-event ingestion shape, payment/refund aggregates, package aggregates). Optimistic locking wired to `CustomersService.updateProfile`/`IdentityModule`; ~30 missing FK constraints added; `TrackingEvent`'s nullable dedup key replaced with a real composite unique constraint; race-safe `FOR UPDATE` triggers enforce refund/payment-allocation aggregates; a trigger maintains `Shipment`'s package-derived aggregate columns. Two genuine concurrency races reproduced with real simultaneous Postgres sessions to prove the `FOR UPDATE` locking actually closes the race, not just the sequential case.
4. **REL-020 — re-verified and fixed.** `notifications-email.job.ts` now resolves `shipment.created`'s actual payload shape (looks up the shipment's owner user) instead of expecting the old pre-resolved shape only `quote.created`/`claim.submitted` (never emitted) produced. Live-verified end to end: `confirmBooking` → outbox row → relay → worker delivery with the correct recipient.
5. **SEC-015 — admin auth rebuilt.** Cognito-token-gated BFF session: `POST /api/auth/login` verifies staff role server-side before setting an httpOnly session cookie plus a separate CSRF cookie (double-submit pattern); the `next.config.ts` `rewrites()` passthrough (couldn't attach the cookie-derived Authorization header) replaced with a real catch-all Route Handler. Live-verified end to end in a real browser: login, dashboard render with correct profile, session cookie genuinely invisible to page JS, sign-out clears server state.
6. **DATA-015 — `REVOKE`-equivalent role and GRANTs.** A new migration creates a `nauterio_app` least-privilege role, granting full CRUD but explicitly withholding UPDATE/DELETE on the five append-only tables and DELETE on `outbox_events` — defense-in-depth alongside the existing triggers. Live-verified at the GRANT level (`permission denied`, not just the trigger's own error), and confirmed a full API boot + real write succeed through the role. Documented gap: no CDK-wired credential-switching yet points ECS's runtime at this role in production.
7. **REL-016 residual — staff list filtering.** `ListShipmentsQueryDto` adds `status`/`createdAfter`/`createdBefore`, applied in `ShipmentsService.list`.
8. **REL-017 residual — query-level visibility push-down.** `tracking.service.ts`'s `where` clause now includes `visibility: {not: "INTERNAL"}` directly, matching `shipments.service.ts`'s existing approach.
9. **SEC-010 item 5 — per-action required-scope metadata table.** `REQUIRED_SCOPE_FIELDS` added to `permission-evaluator.ts`, denying with a caller-bug-shaped message when a record-context call omits a required field, while leaving the coarse guard-time call shape unaffected.
10. **SEC-016 — dependency advisories.** `@nestjs/swagger` `^8`→`^11.4.6`, `vitest` `^2.1.0`→`^4.1.10`. `pnpm audit --audit-level=high`: 12 findings → 0, the last one (a one-patch-behind `js-yaml` pinned inside `@nestjs/swagger`'s own tree) closed via a `pnpm-workspace.yaml` override with a removal note for once `@nestjs/swagger` ships a release that no longer needs it.

## Real bugs found while doing this work, not pre-planned

- `apps/admin`'s CSP was missing `unsafe-eval` in dev, breaking React/Turbopack's own debugging tooling — scoped the exception to non-production.
- Upgrading vitest surfaced that `tsc`-compiled `dist/*.test.js` files were being picked up by Vitest's default include glob alongside the real source tests; Vitest 4 correctly refuses to load them as CommonJS where Vitest 2 apparently didn't care. Fixed by excluding test files from the build output and scoping Vitest's own include glob to `src/`.

## What's left

Nothing tracked by this plan. `pnpm audit --audit-level=high` should be added to CI as the next incremental step (a CI-workflow change, not a code fix, and not attempted as part of this pass) — non-blocking at first, escalating to blocking once the team has a process for triaging new advisories on a normal maintenance cadence.
